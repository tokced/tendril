# 威胁模型（v0.1）

> 先读这个，再安装。Tendril 是一套**远程执行**系统：子端能跑命令、读写文件。安全边界靠「按设备授权 + 显式状态 + 审计」，不靠沙箱。

## 1. 资产

| 资产 | 在哪 | 泄露后果 |
|---|---|---|
| 母端控制令牌（`control.token`） | 母端 `state/`，POSIX 0600；Windows 靠用户目录 ACL | 等同于母端全部权限：能对任何设备下任何任务 |
| 母端 TLS 私钥（`mother-key.pem`） | 母端 `state/`，POSIX 0600；Windows 靠用户目录 ACL | 可冒充母端接收子端连接（配合已泄露邀请） |
| 设备密钥（每设备 32 字节） | 母端台账 + 邀请 | 可冒充该设备拉取并执行任务 |
| 邀请串（`TENDRIL1:…`） | 一次性分发 | 内含地址、设备 id、密钥、母端证书与指纹；15 分钟默认有效 |
| 设备上的文件与命令输出 | 子端 | 按 `roots` 与 `allow_exec` 受限 |
| 审计日志 | 母端 `state/audit.jsonl` | 含设备 id、命令前 200 字符、任务结果摘要 |

## 2. 信任边界

```
agent（大脑/MCP 客户端）
  │ ① MCP stdio：本机进程间，用户级信任
tendril-mcp（桥）
  │ ② HTTP(S) + Bearer 控制令牌：母端鉴权；默认只监听 127.0.0.1
母端（台账/授权/审计）
  │ ③ 子端主动连接，TLS + 设备密钥；证书指纹随邀请固定
子端（执行器）
  │ ④ 本机用户身份（服务模式为 LocalSystem）
文件系统 / 进程
```

- **① 与 ②**：能拿到控制令牌的本机进程可以指挥所有设备。控制令牌不发给模型、不进 MCP 参数。
- **③**：母端不主动连子端；子端连出去，NAT 后也能用。自签证书时子端必须固定邀请里的证书；公网 CA 模式用系统根校验。
- **④**：子端没有沙箱降权；`roots` 只是路径白名单，`allow_exec` 只是开关。真正权限仍是运行它的用户/服务账户。

## 3. 攻击者模型与对策

| 攻击者 | 能力 | 对策 | 残余风险 |
|---|---|---|---|
| 同一局域网/公网的陌生人 | 扫描端口、尝试未授权请求 | 母端默认只监听回环；控制面需 Bearer；设备通道需设备密钥；限流 | 把母端暴露到公网且令牌泄露，等于交出全部设备 |
| 拿到控制令牌的人 | 以母端身份下达任意任务 | 令牌 0600；审计记录每次提交；可逐设备 `deny`/暂停 | 令牌在内存/日志/备份里泄露无法检测 |
| 拿到某台设备密钥的人 | 冒充该设备拉任务、伪造结果 | 设备可 `deny`/`remove-device`，旧密钥立即失效；审计含设备 id | 母端会相信该设备回传的内容（子端本身是可信执行端） |
| 恶意/错误邀请 | 把设备指向错误母端 | 邀请含证书指纹，子端固定校验；`--tls system` 时才走系统根 | 用户复制错邀请、把邀请发给别人 |
| 模型/agent 误操作 | 执行破坏性命令、写错路径 | 双层 `allow_exec`、`roots` 白名单、任务超时与输出截断、`exec` 需人类先确认的红线写在 skill 里 | 模型在允许范围内做错事（删除文件、跑坏脚本）无法自动阻止 |
| 母端本机低权用户 | 读状态目录 | POSIX：`state/` 与令牌 0600。Windows：默认在 `%LOCALAPPDATA%\Tendril`，继承当前用户 ACL；不要放到 `C:\ProgramData` 或共享目录 | 若状态目录放到公共路径或 ACL 被改宽，令牌可被读 |
| 被控设备本地用户 | 查看/篡改子端日志与配置 | 子端日志 0600；密钥只在配置/邀请里 | 本地管理员可完全接管子端（这是设备本体权限问题） |

## 4. 关键控制与代码位置

| 控制 | 位置 | 说明 |
|---|---|---|
| 设备显式状态 `approved` / `enabled` | `mother/server.py`（`Store.add`、`_agent_poll`、`_approve`、`_set_enabled`） | 缺失字段按未批准处理；暂停后子端拿不到任务 |
| 按设备 `allow_exec` + `roots` | 母端台账；子端 `confined` 解析 | 两层独立判定；越界报「不在授权目录内」 |
| 子端执行默认关闭 | `agent/go/main.go`、`agent/tendril_agent.py` | console 运行也需 `--allow-exec`；安装服务默认关闭 |
| 邀请 TTL 与一次性 | `make_invite` / `short_invite` | 默认 900 秒；短链只能取安装脚本 |
| TLS 固定 | 子端 `--ca` 或邀请 `cert` + `fp` | 公网 CA 模式可 `--tls system` |
| 审计 | `Store.audit` | 提交/批准/暂停/取消/结束；命令截断 200 字符 |
| 输出与超时限制 | `EXEC_CAP`、`cap`、`timeout_s` 1–3600 | 防止一次任务把母端上下文打爆 |
| 取消 | `__cancel__` + 进程组终止 | 子端执行期间持续短轮询 |

## 5. 明确不做

- 不是沙箱：不限制子端能跑什么命令，只限制「是否允许跑」和「在哪些目录读写」。
- 不做多租户：一个母端 = 一个所有者。
- 不做远程桌面/屏幕流、不做内核级隔离。
- 不保证对抗设备本地管理员：被控设备的管理员永远能接管子端。

## 6. 报告问题

发现安全问题时不要开公开 issue。用仓库 Security 页的 private reporting，说明版本、复现步骤、影响（是否需要已获邀请/控制令牌）。修复后再公开细节。
